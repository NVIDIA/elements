October brings directional input, more control over spatial navigation, and reusable building blocks for workspaces, backed by earlier feedback on invalid templates. This update covers releases through October 29.

## Before you upgrade

[Viewport](/docs/viewport/) moves out of Core into `@nvidia-elements/viewport`. Install the new package and replace Core Viewport imports with its component entrypoints: `@nvidia-elements/viewport/viewport/define.js`, `@nvidia-elements/viewport/gridlines/define.js`, and `@nvidia-elements/viewport/minimap/define.js`. Core no longer bundles these components. Viewport also replaces the earlier pan and zoom proposal APIs with Invoker commands; use `viewportchange` to observe committed transforms. Viewport remains an evolving API.

## Highlights

### Choose Direction and Intensity with Joystick

The new [Joystick](/docs/elements/joystick/) accepts pointer or arrow-key input and returns normalized coordinates from −1 to 1. Choose circular, square, or single-axis constraints, and let the control return to center or hold its last position after release. Read-only mode displays recorded positions. Applications map these values to their own units and commands, making the component useful for robotics interfaces and simulations without prescribing a control system.

![Joystick displaying live X and Y coordinates below the round movement control](/static/video/releases/10-2026-joystick.webp)

```html
<nve-joystick aria-label="Movement"></nve-joystick>
<nve-joystick aria-label="Turn" constraint="horizontal"></nve-joystick>
```

### Navigate Spatial Views with Shared Controls

The new [Viewport Zoom Range](/docs/viewport/zoom-range/) connects a slider to a viewport through `commandfor`, keeping zoom controls synchronized with the view. Configure `zoom-stops` for meaningful scale steps, and use `--pan-to` and `--zoom-to` commands for custom navigation controls. [Gridlines](/docs/viewport/gridlines/) adds dot and cross patterns alongside lines, so diagrams can use a quieter spatial reference. Accessories now connect correctly even when applications import them separately.

![Zoom slider above pumpkin and ghost emojis on a dot grid](/static/video/releases/10-2026-zoom-controls.webp)

```html
<nve-viewport-zoom-range commandfor="scene" aria-label="Zoom"></nve-viewport-zoom-range>
<nve-viewport id="scene" behavior-pan behavior-zoom style="height: 320px">
  <nve-viewport-gridlines pattern="dots"></nve-viewport-gridlines>
</nve-viewport>
```

### Put Actions Beside Workspace Navigation

[Tabs](/docs/elements/tabs/) adds `nve-tabs-item-group` to place application-owned controls before or after a tab. A close button or actions menu can sit beside its label without becoming part of the tab itself. Arrow keys focus tabs; Tab reaches their accessory controls. Applications handle closing and other actions.

![Workspace tabs with pumpkin and ghost emojis and a close button beside Experiment](/static/video/releases/10-2026-tab-actions.webp)

```html
<nve-tabs behavior-select>
  <nve-tabs-item-group>
    <nve-tabs-item selected>Experiment</nve-tabs-item>
    <nve-icon-button slot="suffix" icon-name="cancel" size="sm" container="flat" aria-label="Close experiment"></nve-icon-button>
  </nve-tabs-item-group>
</nve-tabs>
```

[Tree](/docs/elements/tree/) gains prefix and suffix content, link targets, and Invoker command support. [Icon Button](/docs/elements/icon-button/) now supports icon appearance selection.

### Embed Generated Content with Iframe

The new beta [Iframe](/docs/elements/iframe/) component renders template content in a separate document, making it useful for generated UI, live previews, and embedded examples. It synchronizes the parent theme and adjusts its height as content changes. Supply the body in the default `template` and styles, fonts, or component registrations in a `template` with `slot="head"`; iframe documents do not inherit those resources from the parent page. Iframe shipped in Core 2.16.0 on October 22.

```html
<nve-iframe aria-label="Generated preview">
  <template slot="head">
    <title>Generated preview</title>
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@nvidia-elements/themes/dist/bundles/index.css" />
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@nvidia-elements/themes/dist/fonts/inter.css" />
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@nvidia-elements/styles/dist/bundles/index.css" />
    <script type="module" src="https://cdn.jsdelivr.net/npm/@nvidia-elements/core/dist/bundles/index.min.js"></script>
  </template>
  <template>
    <p nve-text="body">Generated preview content</p>
  </template>
</nve-iframe>
```

### Follow Growing Content with Scroll Box

The new [Scroll Box](/docs/foundations/scroll-box/) keeps the latest text visible as an AI assistant streams a reply or a log gains new entries. Optional edge shadows show where more content is available. In `follow` mode, scrolling away pauses following so people can read earlier content. It ships in the new `@nvidia-elements/foundations` package, which also exposes [shared internationalization support](/docs/foundations/i18n/) for component authors.

![Scroll Box following the newest paragraphs of a streamed assistant reply](/static/video/releases/10-2026-scroll-box.webp)

```html
<nve-scroll-box auto-scroll="follow" scroll-shadow style="height: 240px" aria-label="Assistant conversation">
  <p nve-text="body">Assistant</p>
  <p id="reply" nve-text="body"></p>
</nve-scroll-box>
```

Append incoming response fragments inside the container. Scroll Box follows the growing content without application code setting the scroll position.

```js
const reply = document.querySelector('#reply');
reply.append('Here is the next part of the response.');
```

### Show Ongoing Work with Progress Dot

[Progress Dot](/docs/elements/progress-dot/) adds an animated loading indicator for tasks that have no completion percentage. Place it beside a thinking message or inside a busy button, and give it an accessible name when it conveys status on its own. Small, medium, and large sizes fit different layouts.

![Animated Progress Dot beside a crystal ball and thinking label and inside a busy save button](/static/video/releases/10-2026-progress-dot.webp)

```html
<div nve-layout="row gap:sm align:vertical-center">
  <span id="thinking" nve-text="body">Thinking</span>
  <nve-progress-dot aria-labelledby="thinking"></nve-progress-dot>
</div>
```

### Give Movable Items a Drag Handle

The new [Drag Handle](/docs/elements/drag-handle/) gives movable items a dedicated, labeled grip. Its pressed state marks an item selected for movement, while disabled state keeps unavailable controls visible. Applications manage the movement and reordering, so the same handle can support task lists, workspace panels, or other movable content.

![Drag Handle grips beside emoji rows after Ghosts moves above Pumpkins](/static/video/releases/10-2026-drag-handle.webp)

```html
<nve-drag-handle aria-label="Move training task"></nve-drag-handle>
```

### Repeat Playback or Keep Video in View

New [Loop Button](/docs/media/loop-button/) and [Picture-in-Picture Button](/docs/media/pip-button/) controls connect to a [Media Controller](/docs/media/controller/) through `commandfor`. Loop repeats a recording until users turn it off. Picture-in-picture lets users keep a video visible while working in another window when the browser supports it. Controls reflect the connected video's state, including looping enabled in native video markup.

![Video recording with Loop enabled and an available picture-in-picture control](/static/video/releases/10-2026-media-controls.webp)

```html
<nve-media-controller id="recording">
  <video src="recording.mp4" playsinline loop></video>
</nve-media-controller>
<nve-media-loop-button commandfor="recording"></nve-media-loop-button>
<nve-media-pip-button commandfor="recording"></nve-media-pip-button>
```

### Catch Template Problems Earlier

New [lint checks](/docs/lint/) catch nested interactive elements, unsupported component parents, more than one page shell, invalid numeric and date values, and invalid formatting options. Popover guidance warns about excessive instances. These checks help authors and agents find mistakes while editing templates.

Elsewhere, Monaco integration updates to editor 0.57.0. Fixes improve panel stacking, grid keyboard handling, form label detection, filter-chip sizing, and closed popover layout. Documentation examples also preserve their source more reliably.

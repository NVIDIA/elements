September adds a pan-and-zoom surface for spatial interfaces, more flexible navigation and labels, and native Elements tools for Pi agents, backed by linting that now reaches your Markdown docs.

## Before you upgrade

- **Icons default to outline artwork.** Icons such as `bell`, `checkmark-circle`, `exclamation-circle`, `exclamation-triangle`, and `filter` now render outline artwork instead of filled artwork. Add `appearance="solid"` where you want the filled look. Former `-stroke` names such as `bell-stroke` remain as deprecated aliases, and the `no-deprecated-icon-names` lint rule suggests replacements.
- **Agent setup changed in the CLI.** `nve skills.install` replaces `nve skills.list` and `nve skills.get`, and the recommended MCP server name is now `nvidia_elements`. Rerun `nve project.setup` to migrate existing MCP configuration and tool permissions.

## Highlights

### Navigate Spatial Content with Viewport

The new [Viewport](/docs/elements/viewport/) gives diagrams, graphs, topology maps, and other canvas-style content a shared pan-and-zoom surface. Enable pointer, wheel, keyboard, and pinch navigation with `behavior-pan` and `behavior-zoom`, or set `behavior-pan="space"` to require holding Space before dragging. The `autofit` attribute frames content after the first layout, while `nve-viewport-gridlines` and `nve-viewport-minimap` help people keep their place. Toolbar buttons can control the viewport through Invoker commands such as `--zoom-in` and `--zoom-to-fit`. Viewport is not yet marked stable, so expect API refinements.

```html
<nve-button commandfor="topology" command="--zoom-to-fit">Fit</nve-button>
<nve-viewport id="topology" autofit fit-inset="24" behavior-pan behavior-zoom style="height: 420px">
  <nve-viewport-gridlines></nve-viewport-gridlines>
  <nve-card style="position: absolute; left: 280px; top: 110px; width: 300px">cluster-a</nve-card>
  <nve-viewport-minimap></nve-viewport-minimap>
</nve-viewport>
```

### Organize Navigation with Menu Groups

[Menu](/docs/elements/menu/) now supports `nve-menu-group`, a collapsible header that shows or hides one nested menu, which suits sidebars with sections such as Overview and Data. Groups follow the ARIA disclosure pattern and support `expanded`, `disabled`, and open, close, and toggle commands. Menu items also gain a `prefix` slot for icons, and `density="compact"` on `nve-menu` shows only those icons for narrow navigation rails. Menu Group is not yet marked stable.

```html
<nve-menu-group behavior-expand expanded>
  Overview
  <nve-menu>
    <nve-menu-item current="page"><nve-icon name="home" slot="prefix"></nve-icon> Getting Started</nve-menu-item>
    <nve-menu-item><nve-icon name="bell" slot="prefix"></nve-icon> Alerts</nve-menu-item>
  </nve-menu>
</nve-menu-group>
```

### Use Elements Tools Natively in Pi

The new `@nvidia-elements/pi` package gives [Pi agents](/docs/integrations/pi/) direct access to Elements API documentation, examples, design tokens, icons, package details, and template validation without MCP configuration or a separate CLI process. It also provides an `elements-pi` skill and prompt commands for artifacts, setup checks, new projects, and migrations. After Pi edits an HTML file, the extension validates it and appends any diagnostics to the result.

```shell
pi install npm:@nvidia-elements/pi
```

The [Elements CLI](/docs/cli/) now installs one consolidated `elements` agent skill with `nve skills.install`. [MCP](/docs/mcp/) apps load their styles correctly again, tools return valid structured results for more schemas, and new `/artifact` and `/create-project` prompts replace the earlier introduction, search, and new-project prompts.

### Refine Icons, Tags, and Everyday Components

The `appearance="solid"` attribute now selects filled artwork for 31 icons, including new solid `gear` and `check-badge` variants. [Tag](/docs/elements/tag/) adds `prefix` and `suffix` slots whose icons and dots inherit the tag color, and long labels still truncate cleanly. [Textarea](/docs/elements/textarea/) prefix and suffix slots work again, and its flat container now matches other inputs. [Codeblock](/docs/code/codeblock/) accepts source in slotted `pre` and `code` elements, including escaped HTML. Tree keyboard navigation works again, and Page sizes correctly on mobile browsers with dynamic toolbars.

```html
<nve-tag color="blue-cobalt">
  <nve-icon slot="prefix" name="person" size="sm"></nve-icon>
  reviewers
  <nve-dot slot="suffix" size="sm">3</nve-dot>
</nve-tag>
<nve-icon name="bell" appearance="solid"></nve-icon>
```

### Catch More Issues During Linting

[Elements lint](/docs/lint/) now checks Markdown files under `src/**/*.md`, including rendered markup and HTML in fenced code blocks, so documentation examples get the same checks as application templates. The new `no-invalid-slotted-elements` rule flags direct children that a component does not support, and `no-invalid-page-header-slot` requires page headers inside `nve-page` to use the `header` slot. Existing rules now allow external SVG icon sources, suggest removing an unnecessary `slot="default"`, and account for popovers when counting primary actions.
